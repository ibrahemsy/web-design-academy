# قائمة فحص الإطلاق — أكاديمية تصميم الويب

هذه القائمة مخصصة للتحقق قبل استقبال الطلاب. لا تعتبر عملية البناء الناجحة بديلاً عن اختبار الصلاحيات والبيانات على Supabase فعلياً.

## 1. إعدادات النشر
- [ ] تفعيل GitHub Pages من إعدادات المستودع باستخدام GitHub Actions كمصدر للنشر.
- [ ] التأكد من أن عنوان الموقع هو: https://ibrahemsy.github.io/web-design-academy/
- [ ] التأكد من نجاح مهمتي build و deploy في GitHub Actions.
- [ ] التأكد من أن `flutter analyze` ينتهي دون أخطاء.
- [ ] التأكد من نجاح `flutter test` لاختبارات التنسيق والأدوار وتسلسل تقدم الدروس وحساب نسب الإنجاز.
- [ ] تشغيل `python3 scripts/verify_repository.py` والتأكد من نجاح جميع ثوابت الإصدار.
- [ ] التأكد من عدم وجود مفاتيح Supabase السرية أو service_role في ملفات Flutter أو GitHub.
- [ ] التحقق من أن عنوان Supabase ومفتاح Publishable يعودان إلى المشروع المقصود.

## 2. الحسابات والصلاحيات
استخدم ثلاثة حسابات اختبار مستقلة: طالب، مدرس، ومدير.
- [ ] التسجيل بحساب جديد ينشئ ملف profile بدور student.
- [ ] تسجيل الدخول والخروج واستعادة كلمة المرور تعمل، ويعيد رابط البريد إلى `https://ibrahemsy.github.io/web-design-academy/` ثم يعرض نموذج تعيين كلمة المرور الجديدة.
- [ ] لا يمكن للطالب تغيير دوره عبر واجهة التطبيق أو طلبات العميل.
- [ ] اختبر حساب المدرّس في وضع التعلّم: التسجيل في دورة منشورة، تشغيل درس، حفظ التقدم، أداء اختبار، ثم العودة إلى وضع المدرّس والتأكد من ظهور أدوات الإدارة.
- [ ] لا يفتح التطبيق عند غياب ملف الصلاحيات أو فشل التحقق منه.
- [ ] المدرس يرى الدورات التي يملكها فقط.
- [ ] المدير يستطيع إدارة الأدوار، ولا يمكن إزالة دور آخر مدير.
- [ ] اختبر مستخدماً غير مسجل الدخول على كل مسار خاص.

## 3. الدورات والدروس والفيديو
- [ ] إنشاء دورة كمسودة وتعديلها ونشرها وأرشفتها.
- [ ] لا تظهر المسودات للطلاب.
- [ ] لا يستطيع الطالب التسجيل في دورة غير منشورة.
- [ ] يمكن إضافة درس نصي ودرس فيديو وتعديلهما وحذفهما.
- [ ] رفع MP4 وWebM وMOV والتحقق من رفض الأنواع غير المدعومة.
- [ ] فشل إنشاء سجل الدرس بعد رفع الفيديو لا يترك ملفاً يتيماً.
- [ ] الطالب غير المسجل لا يستطيع تشغيل فيديو درس خاص.
- [ ] معاينة الدرس المنشور تعمل دون تسجيل، ولا تسجل تقدماً.
- [ ] روابط الفيديو الموقعة مؤقتة ولا تكشف ملفات bucket الخاص.
- [ ] تجربة فيديو كبير ومراقبة استهلاك ذاكرة المتصفح.

## 4. تقدم الطالب
- [ ] حفظ موضع المشاهدة واستئناف الفيديو من الموضع السابق.
- [ ] التأكد من حفظ موضع المشاهدة تلقائياً أثناء التشغيل (كل 15 ثانية تقريباً) دون الحاجة إلى إيقاف الفيديو.
- [ ] إغلاق التبويب أو تحديث الصفحة بعد المشاهدة والتحقق من استئناف الدرس من آخر موضع محفوظ.
- [ ] التأكد من عدم إنشاء طلبات حفظ متزامنة متكررة أو أخطاء عند مغادرة صفحة الفيديو.
- [ ] إغلاق مشغل الدرس أثناء وجود عملية حفظ دورية قيد التنفيذ والتحقق من حفظ آخر موضع قبل التخلص من مشغل الفيديو.
- [ ] لا يسجل تقدم المستخدم إلا عند امتلاكه صلاحية التسجيل.
- [ ] تحديث نسبة الإنجاز بعد إكمال الدرس.
- [ ] التحقق من أن الدروس المحذوفة أو المؤرشفة لا تسبب أخطاء في الإحصاءات.

## 5. الاختبارات
- [ ] المدرس ينشئ اختباراً ويعدل عنوانه وأسئلته ودرجة النجاح وحد المحاولات.
- [ ] الطالب المسجل يستطيع قراءة السؤال والخيارات دون الإجابة الصحيحة.
- [ ] لا يستطيع العميل إدخال درجة أو نتيجة محاولة مزيفة.
- [ ] التصحيح واحتساب درجة النجاح يتمان داخل قاعدة البيانات.
- [ ] الحد الأقصى للمحاولات يطبق حتى عند إرسال طلبات مباشرة.
- [ ] الاختبارات ذات المحاولات غير المحدودة تعمل كما هو متوقع.
- [ ] سجل الطالب ونتائج المدرس يعرضان المحاولات الصحيحة فقط.
- [ ] تعديل درجة النجاح لاحقاً لا يغير نتيجة المحاولة التاريخية.

## 6. الشهادات والتقارير
- [ ] لا تصدر الشهادة قبل إكمال جميع الدروس واجتياز الاختبارات المطلوبة.
- [ ] لا يستطيع العميل استدعاء الإصدار لمستخدم آخر أو دورة لا يحق له الوصول إليها.
- [ ] رمز الشهادة فريد وعالي العشوائية (122 بت من العشوائية الفعلية للرموز الجديدة (UUIDv4))، والتحقق العام لا يعرض معلومات إضافية عن الطالب.
- [ ] اسم الطالب وعنوان الدورة محفوظان كلقطة وقت الإصدار.
- [ ] المدرس لا يرى تقارير شهادات دورة مدرس آخر.
- [ ] CSV يدعم العربية بشكل صحيح عند فتحه في Excel.
- [ ] طباعة الشهادة A4 أفقية من Chrome وEdge.

## 7. قاعدة البيانات والأمان
- [ ] مراجعة جميع migrations من 0001 إلى 0028 ومطابقة حالة المشروع الفعلية قبل تطبيق أي ملف.
- [ ] لا تعِد تشغيل migrations على مشروع قائم دون فحص سجل migrations.
- [ ] تشغيل Supabase Security Advisor وPerformance Advisor ومعالجة التحذيرات ذات الصلة.
- [ ] تشغيل `supabase/tests/security_smoke_test.sql` والتأكد من نجاح فحص صلاحيات Data API الافتراضية والحالية، وسياسات الملف الشخصي والدورات والتقدم والتخزين وحارس تغيير الأدوار والشهادات.
- [ ] مراجعة RLS على كل جدول مكشوف عبر Data API.
- [ ] التأكد من أن دوال RPC الحساسة تتحقق من هوية المستخدم ودوره وملكية الدورة داخلياً.
- [ ] مراجعة صلاحيات EXECUTE للدوال، وsearch_path للدوال ذات صلاحيات مرتفعة.
- [ ] التأكد من أن دوال تقرير الشهادات والتحقق الداخلية في `private` غير قابلة للتنفيذ مباشرة من `anon` أو `authenticated`.
- [ ] التأكد من أن `public.verify_course_certificate(text)` و`public.get_course_certificate_report(uuid)` هما غلافا RPC آمنان بصلاحيات `SECURITY DEFINER` و`search_path` فارغ.
- [ ] التأكد من أن دالة التقرير الداخلية تتحقق من هوية المستخدم وملكية الدورة/دور المدير قبل إعادة أي بيانات.
- [ ] التأكد من أن bucket الفيديو خاص وحدود الحجم والأنواع مضبوطة.
- [ ] وضع حدود تنبيه ومراقبة لاستهلاك قاعدة البيانات والتخزين والبريد.

## 8. اختبار المتصفحات وإمكانية الاستخدام
- [ ] اختبار Chrome وEdge وFirefox على سطح المكتب.
- [ ] اختبار عرض الهاتف واللوحي، واتجاه RTL، والنصوص الطويلة.
- [ ] اختبار التنقل بلوحة المفاتيح ووضوح التركيز.
- [ ] التأكد من ظهور حالات التحميل والفراغ والخطأ ورسائل نجاح واضحة.
- [ ] تجربة انقطاع الشبكة أثناء رفع فيديو أو تسليم اختبار.
- [ ] التحقق من عدم تكرار إرسال النماذج عند النقر المتكرر.

## 9. شروط السماح بالإطلاق
لا تبدأ استقبال مستخدمين حقيقيين قبل:
1. نجاح بناء ونشر نسخة الإنتاج.
2. إتمام اختبارات الحسابات الثلاثة من متصفح حقيقي.
3. اجتياز اختبارات عزل بيانات الطلاب والمدرسين.
4. اختبار رفع وتشغيل فيديو فعلي.
5. اختبار رحلة الاختبار والشهادة من البداية إلى النهاية.
6. حفظ نسخة احتياطية وخطة استعادة واضحة.

## سجل الاختبار
سجل لكل اختبار: التاريخ، المتصفح، الحساب/الدور، الخطوات، النتيجة، ورابط الخطأ إن وجد. لا تضع كلمات مرور أو رموز جلسات أو مفاتيح سرية في هذا السجل.
